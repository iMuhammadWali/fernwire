# Fernwire

Free, open-source Windows app that mirrors PC audio to several output devices at
once (e.g. two Bluetooth headphones).

## State
Core, Qt window, icon and tray are done and committed.
- `fernwire/` (Python package):
  - `devices.py` find/classify devices (built-in laptop speakers are never targets,
    matched by name "speakers (realtek" / "speakers (high definition"); `choose_targets`.
  - `delay.py` `DelayLine`: per-device delay, always returns as many frames as it gets.
  - `engine.py` `Engine`: no printing/UI; methods `start/stop/set_targets/set_delay/
    levels/is_target_alive`; events via `on_event(kind, **data)` from threads:
    devices_changed, target_ready, target_lost, source_lost, source_ready. Lost
    targets/source are retried automatically.
  - `settings.py` JSON in `%APPDATA%/Fernwire/settings.json` (theme, per-device
    enabled + delay, keyed by device NAME; remembered devices show as "Not connected").
  - `cli.py` + `main.py`: command-line mode (`python main.py [--virtual]`).
  - `ui/icon.py` the app icon, drawn in code: a source dot with a wire hanging from it and
    two leaves growing alternately, right then left. Two looks that follow the app theme:
    dark = silver on a near-black tile, light = blue (#1c5fd1) on a white tile; lit/filled dot
    while sharing, dim/hollow dot when idle (tray). Window, taskbar and tray icons all switch
    with the theme. `assets/icon.ico`/`icon_light.ico` (+ .png) are generated by
    `python tools/make_icon.py` (for the .exe later). `ui/tray.py` system tray icon.
  - `ui/`: PySide6 window. `tokens.py` themes + QSS + palette, `widgets.py` Switch,
    LevelBar, LinkButton, RailRow/SourceRow/DeviceRow, `window.py` MainWindow +
    DeviceMonitor + native title bar, `demo.py` fake devices/engine, `__main__.py`.
- `design/mockup.html`: visual reference. Tokens live in BOTH it and `ui/tokens.py`:
  change them together.
- Tested so far with a virtual speaker (silent). Real Bluetooth headphones are not yet tested
  with the new engine.

## Tray and icon behavior
- Icon shows in the window title bar, the taskbar (the process sets its own
  AppUserModelID "Fernwire.App", otherwise Windows shows python.exe's icon) and the
  tray. Tray: left click shows/hides the window; right click menu = Show, Start/Stop
  sharing, Quit; tooltip shows status. Closing the window (X) hides it to the tray and
  keeps sharing; only tray "Quit" exits (one-time balloon explains this). Demo mode has no tray.
- Windows 11 may hide a new tray icon in the "^" overflow: drag it out once to pin it.

## Run / test
- Setup: `python -m venv .venv`, `.venv\Scripts\pip install -r requirements-dev.txt`.
- Window: `.venv\Scripts\python -m fernwire.ui`. Dev flags: `--demo` (fake
  devices, no hardware), `--theme auto|dark|light` (this run only), `--state
  idle|sharing|lost|empty|tune` (with --demo), `--screenshot out.png` (window pixels
  only, never the screen).
- CLI: `python main.py [--virtual]`. Tests: `QT_QPA_PLATFORM=offscreen
  .venv\Scripts\python -m pytest -q` (22 tests: classification, delay math, window
  heights, focus, trunk logic, lost state, engine wiring, icons).
- Git: branch `main`, remote `origin` = https://github.com/iMuhammadWali/fernwire.git.

## Name: Fernwire
Fern frond (the plant icon) + wire (cable). Checked Nov 2026: no package on PyPI, no GitHub
repos, no product or trademark found in searches, `.app` `.io` `.dev` looked unregistered
(DNS only, not proof). Closest neighbour: Ferncast (broadcast audio software, different name).
NOT verified: the official USPTO database, registrars, app stores. Rejected: "Audio Splitter"
(paid app of that name), Sprig (SPRIG software trademark + sprig.com), Offshoot (existing
Windows product and company), Frond (registered FROND software trademark), Twig (PHP engine),
Earshot and ManyEars (audio projects), Leafwire/Sproutcast/Branchcast (existing
companies/products). The competitor "Audio Splitter" in the market notes below is a different
product, do not rename it.

## Decisions
- **Platforms:** Windows 10/11 first, then Linux (test logic in WSL2; it has no
  Bluetooth, so real sync needs hardware). Mobile is a separate later project
  (Android only; iOS can't capture system audio).
- **Stack:** Python. Reusable core (`devices`, `delay`, `engine`) plus a thin UI (PySide6/Qt,
  Fusion style). Single `.exe` via PyInstaller, tray app, MIT license.
- **Source is an explicit choice** in the app, not just the Windows default.
- **Sync:** drift between classic Bluetooth devices was not noticeable in early use, so
  auto-calibration (test tone + mic, the "Measure" button) is optional, not the headline.
  Headline is zero-setup: detect, remember, just works. Still test with video (lip-sync).
  Per-device delay and drift are the hard parts.
- **Market:** not novel (Voicemeeter, Audio Splitter/AmpSplit, Airfoil, AmpMe,
  AudioRelay). Windows 11 "Shared Audio" needs LE Audio headphones and supporting hardware,
  while many headphones are classic Bluetooth, so the gap is real for older devices.

## UI direction (see design/mockup.html)
Operate mode: a quiet tool. One window, Segoe UI only, small fixed type scale.
- **Layout:** the source sits at the head of a vertical rail and each device
  branches off it. The rail is one shared trunk, lit from the source down to the
  LAST active device and passing straight by any device that is off or lost. A
  branch lights only for its own active device; a lost/retrying device's branch is
  dashed in the error colour. Footer: status left, one primary button right.
- **Per device:** switch, level bar while sharing, a delay link ("+40 ms delay")
  that opens an inline sync panel (slider + Measure).
- **States:** Ready, Sharing, Device lost ("Lost connection. Retrying…"), No devices
  (teaches the fix, links `ms-settings:bluetooth`), device not connected (dimmed).
- **Themes `dark` and `light`**, as tokens (`data-theme`).
  - dark: near-black, true-neutral greys (equal R/G/B) with an elevation ladder (stage <
    window < title bar/footer/inputs < hover). Silver `#e6e6e6` = active. Error `#d9745b`
    (muted orangish red).
  - light: white ground, blue accent `#1c5fd1`, error `#c62828`.
- **Colour roles:** accent = flowing/active/primary action. Values and inline links
  stay neutral text (underline = clickable). Error colour only on error text. Errors
  also say it in words.
- **Stable boxes rule:** font weight changes and Start/Stop must never resize or
  shift a box. Delay link has no padding and reserves its bold width with a hidden
  `::after` (`data-text`); the level bar's space is always reserved. Measured
  constant: source row 71.8px, device rows 82.8px, window 517.5px across states.
  Verify by measuring in headless Edge, not by eye.
- **Design rules:** avoid the generic look (warm cream + serif + terracotta, glow/pulse dots,
  icon-in-tile cards, uppercase eyebrow on every section). Dark theme: no colour tint in the
  greys and no yellow/orange accents (the error colour is the one orangish red); real surface
  elevation, not flat black. Do not generate Impeccable's PRODUCT.md / DESIGN.md files; the
  skill's reference playbooks were used for guidance only.

## Audit (judged as a Windows desktop app)
Browser-only items (color-scheme, ARIA roles, DOM focus loss) do not apply to Qt.
The mockup passes every desktop-relevant check, measured: all text >= 4.5:1;
control borders, OFF switch and idle rail >= 3:1 (both themes); switch keyboard
focus ring visible; focus kept across re-renders; delay link hit area ~25px;
animation loop runs only while sharing; level bar shows real data under reduced
motion; screen-reader links (switch -> reason, slider -> output). The detector's "flat
type hierarchy" (13/14/15px) is a false positive for Operate mode.

Still to do in the Qt app:
- Native title bar follows the Windows theme (done via DWM; re-check on Windows 10).
- Pixel positions of the rail follow the row layout, not fixed px: test at
  100/125/150/200% display scaling and larger Windows text size.
- Honor Windows high contrast (use system colors) and the "Show animations" setting.
- Accessible names/descriptions are set; screen-reader test still needed.
- Minimum window size; long device names ellipsize; the UI must never block the audio
  threads; idle CPU ~0% (it lives in the tray). Controls >= 24px tall (Windows
  convention is ~32px).
